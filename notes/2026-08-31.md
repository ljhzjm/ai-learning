## 二、今天解决的 4 个核心问题

### 问题 1:Docker Desktop 报 "WSL update required"

**现象**:Docker CLI 装好了(`docker --version` 正常),但 `docker ps` 报 "Docker Desktop is unable to start"。

**根因**(从日志定位):
```
com.docker.backend.exe.wslexec: wsl.exe --version failed
engines: engine linux/wsl failed to start: checking preconditions: WSL update required
```
- Windows 10 自带的是**旧版 inbox WSL**(`wsl --version` 只会打印用法说明)
- Docker Desktop 4.88 要求**新版 WSL**(商店版/MSI 版,2.x,支持 `wsl --version` 命令)
- 内核更新到 WSL2 不够,`wsl.exe` 本体也要是新的

**解决步骤**:
1. 下载 `wsl.2.7.12.0.x64.msi`(247MB,见问题 2 的下载方法)
2. 管理员 PowerShell 安装:`msiexec /i D:\WSL\wsl_update\wsl.2.7.12.0.x64.msi /qb /l*v install.log`
3. 验证:`wsl --version` → 2.7.12(内核 6.18.33.2)
4. 重启 Docker Desktop → `docker ps` 正常,`docker-desktop` 发行版出现在 `wsl -l -v`

**教训**:
- CLI 装好 ≠ 引擎能跑,`docker ps` 才是一票否决的验收标准
- Docker 日志位置:`%LOCALAPPDATA%\Docker\log\host\com.docker.backend.exe.log`

### 问题 2:无代理国内网络,怎么下载 GitHub 的 247MB 文件

**网络实测结论**(这台机器,2026-08-31):
| 通道 | 状态 |
|---|---|
| github.com 网页(HTTPS 443) | ❌ 超时 |
| api.github.com | ✅ 通 |
| GitHub SSH(22 端口) | ✅ 通 |
| 微软商店 / wsl --update | ❌ 超时 |
| 直接下载单连接速度 | ~15KB/s(247MB 要 5 小时) |
| 多连接并行 | ✅ 可叠加,8 线程聚合 ~200KB/s |
| ghproxy 类镜像 | ❌ 基本都挂了 |

**方案:Python 多线程 Range 分块下载 + 断点续传**

原理:HTTP Range 请求(`bytes=起-止`)可以只下载文件的某一段;每条连接都被限速,那就开多条,各自下载一段,最后合并。

配套技巧:
- GitHub API 资产通道绕过被墙的网页域名:`api.github.com/repos/{owner}/{repo}/releases/assets/{id}` + 请求头 `Accept: application/octet-stream`
- 断点续传:每个 part 记录已下载字节数,重试时从 `已下+1` 继续请求

### 问题 3:msiexec /qn 静默安装失败,一点提示都没有

**教训**:
- `/qn`(完全静默)失败时看不到任何错误 → 用 `/qb`(基本界面,弹错误框)+ `/l*v 日志路径`(详细日志)

### 问题 4:C 盘 99% 爆满的排查与清理

**排查方法论(对账法)**:
1. `df -h /c` 看总用量
2. `du -sh /c/目录/*` 逐层下钻,列出各目录占用排序
3. 把找出来的大头**加总对账**,对不上说明还有没扫到的(隐藏目录 `.xxx`、系统还原点、ACL 保护的目录)
4. 常见大头清单:pagefile.sys(虚拟内存)、AppData(微信/QQ/缓存)、回收站、崩溃转储(.hprof)、浏览器缓存、Windows\WinSxS

**本次清理结果:2G → 16G 可用**(清掉 14G):

## 三、常用命令速查(今天实际用过的)

### WSL
```powershell
wsl --version            # 看 WSL 本体版本(旧 inbox 版不支持此命令,输出用法说明)
wsl --status             # 默认发行版/版本/内核版本
wsl -l -v                # 列出所有发行版及版本(1 或 2)
wsl -d Ubuntu            # 启动指定发行版
wsl --set-default-version 2        # 设为默认 WSL2
wsl --import Ubuntu D:\WSL\Ubuntu 镜像.wsl --version 2   # 导入 .wsl 镜像(导入前先建目录!)
wsl -d Ubuntu -- echo ok           # 在 WSL 里执行一条命令并返回
```
- **inbox WSL** = Windows 自带的老版,功能少;**商店版/新版 WSL** = 独立安装的 2.x,`--version` 可查
- 导入安装的发行版没有开始菜单图标,用 `wsl -d <名字>` 启动
- 导入后无用户向导:手动 `useradd -m -s /bin/bash -G sudo 用户名` + `chpasswd` 设密码 + `/etc/wsl.conf` 写 `[user] default=用户名`

### Docker
```powershell
docker --version    # CLI 版本(不代表引擎在跑)
docker ps           # 真正的验收:引擎能响应 = 成功
docker version      # 同时看 Client 和 Server(Server 有版本号说明引擎在线)
```
- 架构:**CLI(客户端)→ Engine(守护进程)**,Docker Desktop 的引擎跑在 WSL2 里的 `docker-desktop` 发行版中
- 验证后端:`wsl -l -v` 里应看到 `docker-desktop` 且 Running

### GitHub SSH
```powershell
ssh-keygen -t rsa -b 4096 -C "邮箱"   # 生成密钥对(id_rsa 私钥 + id_rsa.pub 公钥)
ssh -T git@github.com                 # 测试:成功显示 Hi 用户名!
```
- **原理**:公钥放到 GitHub(Settings → SSH and GPG keys),私钥留在本地;GitHub 用公钥验证你的身份,数据走加密通道
- 私钥=你的身份凭证,**永远不能给别人**;公钥随便公开
- known_hosts:首次连接时记录服务器指纹,之后发现指纹变了就报警 —— 防中间人攻击
