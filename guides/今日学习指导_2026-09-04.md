## 🎯 先懂 5 个新概念(10 分钟)

| 概念 | 一句话解释 |
|---|---|
| **关系型数据库** | 数据存在**表**里(类似 Excel 工作表),行 = 一条记录,列 = 字段 |
| **SQL 是声明式语言** | 你写"**要什么**"(WHERE 条件、要哪些列),不写"怎么算"——怎么算由数据库引擎决定 |
| **主键 / 外键** | 主键 = 一张表里唯一标识一行(如学生 id);外键 = 另一张表里引用这个 id 的列(如选课表里的 student_id) |
| **索引** | 类似书目录:没有它数据库要**全表扫描**(一行行翻),有它能直接跳到目标位置 |
| **执行计划(EXPLAIN)** | 让数据库**打印它打算怎么执行你的查询**——看到 SCAN(全扫)就要警惕,SEARCH(走索引)才高效 |

新建 `src\w2d1_sql_basics\setup.py`(**建表 + 插入数据,今天的所有查询都基于这份数据**):

```python
"""建库播种:3 张表(学生/课程/选课)+ 示例数据。"""
import sqlite3
from pathlib import Path

DB_PATH = Path(__file__).resolve().parents[2] / "school.db"   # 项目根目录

def create_db():
    if DB_PATH.exists():
        DB_PATH.unlink()          # 重复跑时重建,保证数据一致
    conn = sqlite3.connect(DB_PATH)
    cur = conn.cursor()
    cur.executescript("""
    CREATE TABLE students (
        id INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        class_id INTEGER NOT NULL
    );
    CREATE TABLE courses (
        id INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        credit REAL NOT NULL
    );
    CREATE TABLE enrollments (
        student_id INTEGER NOT NULL,
        course_id INTEGER NOT NULL,
        score REAL,                          -- NULL = 缺考
        PRIMARY KEY (student_id, course_id)
    );
    """)
    students = [(1, "张伟", 1), (2, "李娜", 1), (3, "王强", 2),
                (4, "赵敏", 2), (5, "陈晨", 2), (6, "刘洋", 1)]
    courses = [(1, "语文", 4), (2, "数学", 4), (3, "英语", 3), (4, "体育", 1)]
    enrollments = [
        (1, 1, 92), (1, 2, 85), (1, 3, 88),
        (2, 1, 78), (2, 2, None), (2, 4, 90),      # 李娜数学缺考
        (3, 1, 61), (3, 2, 95), (3, 3, 73),
        (4, 2, 82), (4, 3, None),                  # 赵敏英语缺考
        (5, 1, 55), (5, 2, 68), (5, 3, 70), (5, 4, 88),
        (6, 1, None), (6, 2, 66),                  # 刘洋语文缺考
    ]
    cur.executemany("INSERT INTO students VALUES (?, ?, ?)", students)
    cur.executemany("INSERT INTO courses VALUES (?, ?, ?)", courses)
    cur.executemany("INSERT INTO enrollments VALUES (?, ?, ?)", enrollments)
    conn.commit()
    conn.close()
    print(f"✅ 已建库 {DB_PATH}")

if __name__ == "__main__":
    create_db()
```

新建 `src\w2d1_sql_basics\repl.py`(**SQL 练习台**:输入一行 SQL 出结果,`exit` 退出):

```python
"""SQL 交互练习台:输一行 SQL 看结果。"""
import sqlite3
from pathlib import Path

DB_PATH = Path(__file__).resolve().parents[2] / "school.db"
conn = sqlite3.connect(DB_PATH)
print(f"已打开 {DB_PATH.name},输入 SQL(exit 退出):")
while True:
    sql = input("sql> ").strip()
    if not sql:
        continue
    if sql.lower() in ("exit", "quit"):
        break
    try:
        rows = conn.execute(sql).fetchall()
        for r in rows:
            print(r)
        print(f"── {len(rows)} 行")
    except Exception as e:
        print(f"❌ {type(e).__name__}: {e}")
```

## 📖 第 2 步:5 类查询逐一手写(60 分钟)

在 repl.py 里逐条敲(先想答案再敲,别照抄),每条都看懂**为什么**返回这些行。

### 类 1:基础查询(SELECT / WHERE / ORDER BY / LIMIT / DISTINCT)

```sql
SELECT * FROM students WHERE class_id = 1;                 -- 1 班学生(WHERE 过滤行)
SELECT name, credit FROM courses ORDER BY credit DESC;     -- 按学分降序(ORDER BY 排序)
SELECT * FROM enrollments ORDER BY score DESC LIMIT 3;     -- 最高 3 个成绩(LIMIT 截断)
SELECT DISTINCT class_id FROM students;                    -- 有哪些班级(DISTINCT 去重)
```

> 要点:`SELECT 列` 决定要哪些列,`WHERE` 决定要哪些行,`ORDER BY` 只影响显示顺序,`LIMIT` 最后执行。NULL 排序时默认最小。

### 类 2:聚合与分组(COUNT / AVG / GROUP BY / HAVING)

```sql
SELECT COUNT(*) FROM students;                             -- 总人数
SELECT AVG(score) FROM enrollments;                        -- 全体平均分(NULL 自动被忽略!)
SELECT student_id, AVG(score) AS avg_score
FROM enrollments GROUP BY student_id;                      -- 每个学生的平均分
SELECT student_id, AVG(score) AS avg_score
FROM enrollments GROUP BY student_id HAVING AVG(score) >= 80;   -- 只要平均分 ≥80 的
```

> 要点:执行顺序是 **WHERE 过滤行 → GROUP BY 分组 → HAVING 过滤组 → SELECT 输出**。所以「每个学生的平均分」这类"按 XX 每个"问题,答案永远是 GROUP BY XX;对**分组结果**再提条件必须用 HAVING(WHERE 管不到分组后的东西)。`AS` 给列起别名,HAVING 里才能用 `AVG(score)` 这样的聚合函数。

### 类 3:多表 JOIN(INNER / LEFT)

```sql
-- INNER JOIN:三表连查「谁 选了哪门课 考了多少分」
SELECT s.name, c.name, e.score
FROM enrollments e
JOIN students s ON s.id = e.student_id
JOIN courses c ON c.id = e.course_id;

-- LEFT JOIN:每个学生的选课数,没选课的也要列出(补 0)
SELECT s.name, COUNT(e.course_id) AS cnt
FROM students s
LEFT JOIN enrollments e ON e.student_id = s.id
GROUP BY s.id;
```

> 要点:① 缩写 `e`/`s`/`c` 叫**表别名**,写在 FROM 后面;② `ON` 写的是"两张表怎么对上"(外键关系);③ INNER JOIN 只保留两边都匹配的行,LEFT JOIN **保留左表全部行**,右边没匹配的填 NULL —— 这就是"没选课的学生也列出"的写法;④ COUNT(列名) 不数 NULL,所以刘洋的 cnt 会是 0。

### 类 4:子查询(WHERE 里 + FROM 里)

```sql
-- WHERE 里的子查询:数学 ≥90 分的学生名字
SELECT name FROM students WHERE id IN (
    SELECT student_id FROM enrollments WHERE course_id = 2 AND score >= 90
);

-- FROM 里的派生表:平均分前 3 的学生(子查询结果当一张表用)
SELECT s.name, t.avg_score FROM (
    SELECT student_id, AVG(score) AS avg_score
    FROM enrollments GROUP BY student_id
    ORDER BY avg_score DESC LIMIT 3
) t JOIN students s ON s.id = t.student_id;
```

> 要点:子查询 = **查询里再嵌一个查询**。WHERE 子查询常用于 `IN (...)`;FROM 子查询(派生表)必须有别名(第二个例子的 `t`),它先把中间结果算好,外层再基于它查。什么时候用?先问自己"我要的答案能不能用一个查询直接得到",不能就先想"中间需要哪一步"。

### 类 5:EXPLAIN 看懂执行计划

```sql
EXPLAIN QUERY PLAN SELECT * FROM enrollments WHERE student_id = 3;
-- 输出:SCAN enrollments   ← 无索引,全表扫描

CREATE INDEX idx_enr_student ON enrollments(student_id);   -- 建索引

EXPLAIN QUERY PLAN SELECT * FROM enrollments WHERE student_id = 3;
-- 输出:SEARCH enrollments USING INDEX idx_enr_student (student_id=?)   ← 走索引
```

> 要点:① `EXPLAIN QUERY PLAN` 不真正执行查询,只打印**执行计划**;② `SCAN` = 一行行翻全表,数据大了会慢;`SEARCH ... USING INDEX` = 直接按索引定位,快;③ 看到计划里出现 SCAN 就要问自己:这个 WHERE 的列有没有索引?④ 大表上频繁 WHERE 的列就该建索引 —— 周二在 PG 里用 `EXPLAIN ANALYZE` 还能看到**真实耗时**。
