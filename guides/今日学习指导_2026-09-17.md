昨天你亲手验证了一件反直觉的事:**prompt 里写了「只输出类别名称,不要解释」,zero-shot 就是 8/8 干净**——约束一旦写死,few-shot 根本没发挥空间。但注意"写死"两个字有多脆:你换个说法、换个模型、换个任务,它就漂了。今天要做的,是**把"格式"从模型的自觉,变成机制上的强制**。

## 🎯 先懂三档强度(10 分钟)

| 档位 | 手段 | 保证什么 | 不保证什么 |
|---|---|---|---|
| ① 纯 prompt | 自然语言约束 | 什么都不保证 | 全靠模型自觉 |
| ② JSON mode | `response_format={"type":"json_object"}` | **语法上合法的 JSON** | **符合你要的字段结构** |
| ③ tool 强制 | `tools` + `tool_choice` | **字段名/类型按 schema 走** | 值对不对(那是模型的事) |

关键认知:**②和③之间的鸿沟,是今天最值钱的一课**——"合法 JSON" 和 "你能用的 JSON" 完全是两码事。

```python
"""发一次 chat 请求,返回原始 response dict。"""

import httpx

from w3d4_structured_output.settings import Settings

MAX_TOKENS = 400


def call(s: Settings, messages: list[dict], **extra) -> dict:
    """extra 用来透传 response_format / tools / tool_choice 等。"""
    r = httpx.post(
        f"{s.base_url}/chat/completions",
        headers={"Authorization": f"Bearer {s.api_key}"},
        json={"model": s.model, "messages": messages, "max_tokens": MAX_TOKENS, **extra},
        timeout=60,
    )
    r.raise_for_status()
    return r.json()
```

## 📦 第 2 步:定 schema(15 分钟)—— schema.py

```python
from pydantic import BaseModel


class Extraction(BaseModel):
    """一条新闻的抽取结果。字段名用英文——它是要进数据库/接口的标识符,
    不是给人看的标签。"""

    name: str | None = None      # 人名
    company: str | None = None   # 公司名
    place: str | None = None     # 地点
    date: str | None = None      # 日期
    amount: str | None = None    # 金额
```

**全部 Optional 是有意的**:字段缺失 ≠ 抽取失败。真人名抽不到是"这条新闻没有",不是"程序错了"。区分这两件事,是重试逻辑该不该触发的分界线。

## 📦 第 4 步:JSON mode(25 分钟)

```python
def extract_json_mode(s, news) -> dict:
    r = call(
        s,
        [{"role": "user", "content": PROMPT_ONLY.format(news=news)}],
        response_format={"type": "json_object"},
    )
    return json.loads(r["choices"][0]["message"]["content"])
```

### ⚠️ 坑 1:prompt 里必须出现 "json" 字样

我拿你的 key 实测过了,不加直接 400:

```
{"error":{"message":"Prompt must contain the word 'json' in some form to
use 'response_format' of type 'json_object'.","type":"invalid_request_error"}}
```

上面 `PROMPT_ONLY` 里的「以 json 输出」就是为它准备的。**故意试试把这个词删掉,亲眼看一次 400**——比记住这句话有用。

### ⚠️ 坑 2:JSON mode 只保证"合法",不保证"是你要的"

实测(输入「抽取人名和公司:李明在星辰科技上班。」)返回的是:

```json
{"type": "json_object", "name": "李明", "company": "星辰科技"}
```

**它把我 `response_format` 的参数当字段抄进了结果里。** 这是一段完全合法的 JSON——`json.loads` 一点脾气没有——但你的程序拿到 `type` 这个键会懵。

**这就是"合法 JSON ≠ 可用的 JSON"。** 也是为什么必须有下一步。

## 📦 第 5 步:tool 强制(30 分钟)—— 今天真正的正解

```python
TOOLS = [{
    "type": "function",
    "function": {
        "name": "emit_extraction",
        "description": "输出新闻抽取结果",
        "parameters": Extraction.model_json_schema(),   # Pydantic 直接生成 schema
    },
}]


def extract_tool(s, news) -> dict:
    r = call(
        s,
        [{"role": "user", "content": PROMPT_TOOL.format(news=news)}],
        tools=TOOLS,
        tool_choice={"type": "function", "function": {"name": "emit_extraction"}},
    )
    msg = r["choices"][0]["message"]
    args = msg["tool_calls"][0]["function"]["arguments"]
    return json.loads(args)
```

### ⚠️ 坑 3:tool 调用的三个反直觉点(我实测确认过)

1. **结果不在 `content` 里**。`content` 是**空字符串**,东西全在 `tool_calls[0]["function"]["arguments"`
2. **`arguments` 是字符串,不是 dict**——得再 `json.loads` 一次。模型吐的是"JSON 文本",不是结构化对象
3. `finish_reason` 是 `"tool_calls"`,不是 `"stop"`。写重试逻辑时按这个判断有没有拿到东西

注意 `Extraction.model_json_schema()` 这一句——**schema 只写一遍**,Pydantic 同时负责"告诉模型要什么形状"和"校验模型给的东西",两边同一份定义,不会漂。这是今天最漂亮的地方。

## 📦 第 6 步:Pydantic 校验 + 失败重试(25 分钟)

```python
from pydantic import ValidationError


def extract_with_retry(s, news, fn, tries: int = 3) -> tuple[Extraction | None, int]:
    """返回 (结果, 实际尝试次数)。全失败返回 (None, tries)。"""
    for i in range(1, tries + 1):
        try:
            return Extraction.model_validate(fn(s, news)), i
        except (json.JSONDecodeError, ValidationError, KeyError, IndexError) as e:
            print(f"    第 {i} 次失败: {type(e).__name__}: {str(e)[:60]}")
    return None, tries
```

**重试不是万能药**:同一个 prompt 重发往往还是错。真正的重试要带信息——把报错塞回去让模型改:

```python
        # 进阶:把错误回灌进对话,让模型自己修
        messages = messages + [
            {"role": "assistant", "content": 上次的原始输出},
            {"role": "user", "content": f"上面的 json 不符合要求:{错误信息}。请只输出修正后的 json。"},
        ]
```
