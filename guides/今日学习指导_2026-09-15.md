昨天你拿到的是**事后账**(发完请求,usage 才告诉你花了多少 token)。今天学**事前账**:请求还没发,先估出要花多少 token、多少钱。这是做 LLM 应用的基本功——预算控制、防爆上下文窗口、选模型,全靠它。

## 🎯 先懂两个公式(15 分钟)

**估算公式(启发式,按文本类型挑粒度)**:

| 文本 | 粗粒度口诀 | 细粒度 | 昨天的实测打脸 |
|---|---|---|---|
| 中文 | token ≈ 字数 × 1.5 | 按字数拟合 | 「我爱编程」4 字 = 6 tokens ✓(1.5/字) |
| 英文 | token ≈ 词数 × 1.3 | **token ≈ 字符数 ÷ 4** | 「I love programming」3 词 = **7 tokens** ✗——长词(programming)会被拆碎,词数法失灵,字符数法更稳 |

**计价公式(单位坑重点圈出来)**:

```
成本 = prompt_tokens/1_000_000 × 输入单价 + completion_tokens/1_000_000 × 输出单价
```

价格页标的都是「**每百万 tokens** 多少元」,除 1,000,000 是写代码时最容易错的地方(差 1000 倍)。另外记住一个普遍规律:**输出单价通常比输入贵好几倍**,所以省钱第一招是让模型回答短一点。

还有一条暗线:昨天 usage 里出现过 `prompt_cache_hit_tokens` 字段——多轮对话第二轮起,前面历史会命中缓存,**缓存价更便宜**。今天先不管,周六做网关时它会回来。

```python
def estimate_tokens_zh(text: str) -> int:
    """中文:字数 × 系数(初版 1.5,校准后回填)。"""
    return int(len(text) * 1.5)


def estimate_tokens_en(text: str) -> int:
    """英文:字符数 ÷ 4(字符数法,长词也不慌)。"""
    return int(len(text) / 4)
```

## 📦 第 3 步:calibrate.py——实测校准,今天的核心(40 分钟)

思路:取一批**不同长度**的文本,逐条发 API 拿真实 prompt_tokens,然后**线性拟合**出「每字多少 token」和「固定开销」。为什么是线性:tokenizer 对每个汉字的行为很稳定(斜率),而每条消息都有 role/格式的包装 token(截距)。

```python
import statistics

import httpx

from w3d2_token_cost.settings import Settings

# 5 段不同长度的中文样本(自己写,10~400 字,题材随意)
SAMPLES_ZH = [
    "今天天气不错。",
    "今天天气不错,适合出门散步,顺便去菜市场买点水果回来。",
    # ... 自己补到 5 段,长度拉开
]


def real_tokens(s: Settings, text: str) -> int:
    r = httpx.post(
        f"{s.base_url}/chat/completions",
        headers={"Authorization": f"Bearer {s.api_key}"},
        json={"model": s.model, "messages": [{"role": "user", "content": text}], "max_tokens": 1},
        timeout=60,
    )
    r.raise_for_status()
    return r.json()["usage"]["prompt_tokens"]


def main() -> None:
    s = Settings()
    lengths = [len(t) for t in SAMPLES_ZH]      # x:字数
    tokens = [real_tokens(s, t) for t in SAMPLES_ZH]  # y:真实 token
    for length, token in zip(lengths, tokens):
        print(f"字数 {length:4d} -> {token:4d} tokens")
    slope, intercept = statistics.linear_regression(lengths, tokens)
    print(f"\n拟合:token = {slope:.3f} × 字数 + {intercept:.2f}")
    print(f"结论:中文每字约 {slope:.2f} token,每条消息固定开销约 {intercept:.0f} token")
```

跑完你会得到**只属于你的模型+tokenizer** 的系数(大概率:斜率 1.3~1.6,截距 3~5)。把这个斜率回填到 estimate.py,粗估算就升级成校准估算。英文同理,把 x 换成字符数再拟合一轮(词数法就别拟合了,昨天已经被打脸)。

> `statistics.linear_regression` 是 Python 3.10+ 标准库自带的最小二乘,零依赖。

## 📦 第 4 步:cost.py——把 token 换成钱(30 分钟)

```python
def estimate_cost(s: Settings, prompt: str, max_out: int) -> tuple[float, float]:
    """返回 (预估成本, 实际成本):实际成本需真实发一次请求。"""
    est_in = estimate_tokens_zh(prompt)          # 用校准后的系数
    est_cost = est_in / 1_000_000 * s.price_in_per_m + max_out / 1_000_000 * s.price_out_per_m

```
