## 🎯 先懂 compose 是什么(10 分钟)

| 概念 | 一句话解释 |
|---|---|
| **compose** | 把"一堆 docker run 命令"写成一个 YAML 声明文件,描述最终状态,不用管执行顺序 |
| **service 服务** | YAML 里的一个条目 = 一个容器;`db`/`cache`/`api` 就是三个服务 |
| **服务名 = 域名** | compose 自动建一个网络,三个服务互访直接用名字:`api` 里连 `db:5432` —— 不再需要 `host.docker.internal` |
| **depends_on** | 声明启动依赖,但**只保证"启动了"**,不保证"就绪了"(PG 可能还在初始化) |
| **healthcheck** | 探活命令;配合 `condition: service_healthy` 才是"等它真正能干活" |

**一句话串起来**:compose = 声明式编排;服务名互连 + 健康检查 + 命名卷,三个知识点今天一次用全。

## 📦 第 2 步:写 docker-compose.yml(40 分钟,逐行读懂)

新建文件夹 `practice/w2d7-compose`,在里面建 `docker-compose.yml`:

```yaml
# 一条命令拉起 后端+数据库+缓存:docker compose up -d
services:
  db:                                   # 服务 1:PostgreSQL
    image: postgres:16-alpine           # 本地已有,不会去 Docker Hub 拉
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres       # 练习用;生产换成密钥管理
      POSTGRES_DB: todo                 # 首次启动自动建库(宿主 pg-school 手建过,对比一下)
    volumes:
      - pg-data:/var/lib/postgresql/data   # 命名卷:数据比容器活得久
    ports:
      - "55432:5432"                    # 宿主 5432 被 pg-school 占了,故意换个口
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d todo"]
      interval: 5s
      timeout: 3s
      retries: 10

  cache:                                # 服务 2:Redis
    image: redis:7-alpine
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10
    # 故意不挂卷:缓存丢了可以重建,数据不金贵 —— 对比 db 服务想一想为什么待遇不同

  api:                                  # 服务 3:FastAPI,复用周六的 Dockerfile
    build: ../w2d3-sqlalchemy-todo
    environment:
      # 服务名就是域名!告别 host.docker.internal
      TODO_DATABASE_URL: postgresql+psycopg://postgres:postgres@db:5432/todo
      TODO_REDIS_URL: redis://cache:6379/0
    ports:
      - "8000:8000"
    depends_on:
      db:
        condition: service_healthy      # 等 PG 真正就绪,不是"启动了"就行
      cache:
        condition: service_healthy

volumes:
  pg-data:                              # 顶层声明,才会创建命名卷
```

**写之前问自己三个问题**(写在注释里也行):
1. `depends_on: db` 不加 `condition: service_healthy` 会发生什么?(答:api 可能比 PG 初始化更快启动,连库报错)
2. 为什么 `db` 挂卷、`cache` 不挂?(答:业务数据 vs 可重建的缓存)
3. `ports` 里 `55432:5432` 左边是什么、右边是什么?(答:宿主端口:容器端口)

## 🏁 验收挑战(40 分钟,独立完成)

1. **一条命令复活挑战**:`down -v` 之后,现在库里啥都没了。目标:**只执行 `docker compose up -d` 一条命令**,整栈自动复活(自动建表 + 起服务)。提示:给 Dockerfile 加一个 `entrypoint.sh`——`docker compose run --rm api <命令>` 传参时直接执行参数命令,否则先 `alembic upgrade head` 再 exec uvicorn:
   ```sh
   #!/bin/sh
   set -e
   if [ "$#" -gt 0 ]; then exec "$@"; else alembic upgrade head; exec uvicorn w2d3_sqlalchemy_todo.main:app --host 0.0.0.0 --port 8000; fi
   ```
   Dockerfile 里:`COPY entrypoint.sh ./` + `ENTRYPOINT ["sh", "./entrypoint.sh"]`,然后 `docker compose up -d --build`。
   ⚠️ **entrypoint.sh 必须用 LF 行尾保存**(VS Code 右下角点 CRLF → 选 LF),CRLF 会导致 `#!/bin/sh\r` 报错——你踩过 GBK/CRLF 的坑,这次提前防住。
2. `docker compose exec api python -c "import urllib.request; print(urllib.request.urlopen('http://api:8000/todos').status)"` —— 容器里用**服务名**访问自己,证明"服务名=域名"。

4. 把 `api` 的宿主端口从 8000 改成 8002,`docker compose up -d` 后访问 8002 —— 证明端口映射是一处配置。
