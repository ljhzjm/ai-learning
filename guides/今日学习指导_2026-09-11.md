## 🎯 先懂 5 个概念(20 分钟)

| 概念 | 一句话解释 |
|---|---|
| **image 镜像** | 只读的"软件打包模板",含代码+依赖+运行时,由多层(Layer)叠成 |
| **container 容器** | 镜像的**运行实例** = 镜像 + 一个可写层;同一镜像能起无数个容器,互相隔离 |
| **Dockerfile** | 镜像的"菜谱",每条指令(RUN/COPY)生成一层;改一行只重建后续层 |
| **volume 卷** | 数据挂载点,容器删除数据还在。PG/Redis 的数据都存在卷里——所以容器随便删,库不丢 |
| **network 网络** | 容器间的"局域网"。默认 bridge 网络里容器名就是域名;宿主机用 `-p` 发布端口 |

**一句话串起来**:Dockerfile 造镜像 → 镜像跑起来是容器 → 容器要留数据挂卷 → 容器要互连进网络。

## 📦 第 1 步:写 Dockerfile(40 分钟)

在项目根目录(`D:\ITstudy\ai-learning\practice\w2d3-sqlalchemy-todo`)操作。

**0. 先导出依赖清单**。项目用 uv_build 当构建后端,`pip install .` 在镜像里会报错,标准做法是导出 pip 能装的 requirements.txt:

```powershell
uv export --no-hashes -o requirements.txt
```

**1. 写 `.dockerignore`**(项目根目录,新建文件)。没有它,`.venv` 几百 MB 会被塞进构建上下文,又慢又危险:

```
.venv
.env
__pycache__
tests
*.db
```

> **为什么 `.env` 不能进镜像?** 镜像可能被推送到公共仓库/传给同事,.env 里的密码就泄露了。运行时用 `-e` 传环境变量——记住这条,面试常问。

**2. 写 `Dockerfile`**(逐行读懂,每行的作用都注释好了):

```dockerfile
# 基础镜像:官方 python,已带 pip;slim 是瘦身版(没有编译工具链,体积小)
FROM python:3.13-slim

# 容器内的工作目录(不存在会自动建;后面的 COPY/RUN 都相对它)
WORKDIR /app

# 先只拷依赖清单 —— 依赖变化频率低,这层能命中构建缓存
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt

# 再拷源代码 —— 改代码只重建这一层之后的层(依赖层缓存命中,秒级重建)
COPY src ./src

# 声明监听端口(只是文档性质,真正发布端口靠 docker run -p)
EXPOSE 8000

# 容器启动时执行的命令(前台进程!容器生命周期 = 该进程生命周期)
CMD ["uvicorn", "w2d3_sqlalchemy_todo.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

> pip 装不动(网络慢)时,把 RUN 那行换成清华源:
> `RUN pip install --no-cache-dir -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

**理解分层缓存**(今天最重要的认知):`docker build` 每条指令一层。依赖清单没变 → 依赖层直接复用缓存;代码变了 → 只从 `COPY src` 那层开始重建。这就是为什么 **COPY requirements.txt 要单独一行放在 COPY src 前面**。

## 🚀 第 3 步:跑容器 + 验证(40 分钟)

容器里的应用要访问**宿主机上已发布的** PG/Redis,用 Docker Desktop 内置域名 `host.docker.internal`:

```powershell
docker run -d --name todo-api -p 8000:8000 `
  -e TODO_DATABASE_URL=postgresql+psycopg://postgres@host.docker.internal:5432/todo `
  -e TODO_REDIS_URL=redis://host.docker.internal:6379/0 `
  todo-api
```

> 环境变量名要 `TODO_` 前缀(pydantic-settings 的 env_prefix,昨天刚踩过);PG 是 trust 认证所以没密码。**注意别覆盖宿主机已有的 8000 端口**——如果昨天练习时服务还开着,先关掉。

验证四连:

```powershell
docker ps                        # pg-school / redis-cache / todo-api 三容器同框(周末 compose 的雏形!)
curl http://127.0.0.1:8000/todos # 200 —— 应用在容器里跑起来了
docker exec -i redis-cache redis-cli GET todos:list   # 有内容!容器里的应用把缓存写进了宿主 Redis
docker logs -f todo-api          # 看容器日志(Ctrl+C 退出;注意 uvicorn 的启动输出)
```

再加一发昨天的限流验证,确认容器里跑的应用限流照常:

```powershell
for /l %i in (1,1,15) do curl -s -o nul -w "%{http_code} " http://127.0.0.1:8000/todos
```

还是 `200×N → 429×N` ——**昨天的成果被完整装进了镜像**,这就是"打包"的意义。

**进去看看**(容器 = 一个迷你 Linux):


## 🧪 第 4 步:volume 和 network 动手实验(30 分钟)

**volume —— 数据比容器活得久**(用刚拉取的 python:3.13-slim 当实验容器):

```powershell
docker volume create demo-vol
docker run --rm -v demo-vol:/data python:3.13-slim sh -c "echo hello > /data/a.txt"
docker run --rm -v demo-vol:/data python:3.13-slim cat /data/a.txt   # hello —— 第一个容器早死了,数据还在!
docker volume ls                                                  # pg-school/redis-cache 的数据卷也在这里
```

**network —— 容器名就是域名**:

```powershell
docker network ls               # 看看现有网络;默认 bridge 里容器互访要靠 IP,不稳定
docker network create todo-net  # 自建网络:容器加入后,互相用容器名直连
```

> 剧透周日:docker-compose 会自动建一个网络,三个容器用**服务名**互连——今天建网络只是先混个脸熟,真正的直连体验在明天。
