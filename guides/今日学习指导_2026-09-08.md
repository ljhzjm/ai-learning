周一手写 SQL(SQLite)→ 周二在 PG 里手写 SQL。今天开始**不再手写 SQL 字符串**了:表变类、行变对象、查询用 `select()`。这就是 ORM(Object-Relational Mapping),FastAPI 项目里操作数据库的标准方式。

**为什么需要 ORM?** 手写 SQL 的问题是:① 结果是一堆元组,得自己转成对象;② 字段改名要满仓库改 SQL 字符串;③ 字符串拼接有注入风险。ORM 让你"操作对象",SQL 由它替你生成。

**今天的两个设计决定**:
1. **先学同步 Session,加餐给 AsyncSession 对比**(计划表里建议 AsyncSession,但今天第一次接触 ORM,同步版教程生态最大、坑最少;两者的模型/查询 API **100% 相通**,只是加 `await`。项目实战时切 AsyncSession 只改十几行——加餐里有完整对比);
2. **待办 API 用独立数据库 `todo`**(和练习库 school 分开,一个应用一个库,数据互不污染);
3. **驱动用 psycopg 3**(`psycopg[binary]`):SQLAlchemy 自己不直接连库,靠"驱动"翻译,psycopg 3 是官方当前推荐。

## 🎯 先懂 5 个概念(10 分钟)

| 概念 | 一句话解释 |
|---|---|
| **ORM** | 表 ↔ Python 类:一行 = 一个对象,一列 = 一个属性。你操作对象,SQL 由 SQLAlchemy 生成 |
| **Engine** | 和数据库的"专线电话":管理**连接池**,负责把 Python 翻译成 PG 方言的 SQL。**整个应用只建一个** |
| **Session** | "工作单元":`add()` 不立刻发 SQL,`commit()` 时才把本次改动打包成 INSERT/UPDATE 发出去;`close()` 归还连接 |
| **Model / Metadata** | 继承 `Base` 的类 = 一张表;`Base.metadata.create_all(engine)` 按类定义**自动建表**(今天用,周四换成 Alembic) |
| **relationship / 外键** | 给类之间建立引用:访问 `student.enrollments` 自动发 JOIN 查询,不用手写 |

## 📖 第 2 步:模型声明 models.py + schemas.py(15 分钟)

新建 `src\w2d3_sqlalchemy_todo\models.py`:

```python
"""SQLAlchemy 模型声明:一张 Todo 表。"""
from sqlalchemy import String
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

class Base(DeclarativeBase):
    pass                    # 所有模型继承 Base,SQLAlchemy 据此知道哪些类是表

class Todo(Base):
    __tablename__ = "todos"
    id: Mapped[int] = mapped_column(primary_key=True)    # PG 里生成 SERIAL
    title: Mapped[str] = mapped_column(String(100))      # VARCHAR(100),非空
    done: Mapped[bool] = mapped_column(default=False)    # 插入时不写就填 False

    def __repr__(self):
        return f"<Todo {self.id}: {self.title!r} done={self.done}>"
```

要点:
- **SQLAlchemy 2.0 风格**用 `Mapped[...]` 类型标注 + `mapped_column()`;老教程里 `id = Column(Integer, primary_key=True)` 是 1.x 写法,看到要认识,但新代码别那样写;
- `Mapped[str]` = 非空列,`Mapped[str | None]` = 可空列 —— **是否 Optional 就是是否允许 NULL**;
- `default=False` 是 Python 侧默认:插入时该属性没赋值,SQLAlchemy 自动填 False(还有个 `server_default`,是建表时写进 DDL 的数据库侧默认,今天不用)。

`schemas.py` 照抄 w1d7 的,**但 TodoOut 加一行关键的配置**:

```python
from pydantic import BaseModel, ConfigDict, Field

class TodoIn(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    done: bool = False          # 建待办时可以不传,默认 False
class TodoUpdate(BaseModel):
    title: str | None = Field(default=None, min_length=1, max_length=100)
    done: bool | None = None
class TodoOut(TodoIn):
    id: int
    model_config = ConfigDict(from_attributes=True)
    # ↑ 关键!让 pydantic 能直接读 ORM 对象的属性。
    # 没有它,接口返回 Todo 实例(而不是 dict)时会报响应验证错误(500)
```

> 这是今天最容易踩的坑:w1d7 的接口返回的是 **dict**,pydantic 天生会处理;今天返回 **ORM 对象**,必须开 `from_attributes=True`。

## 📖 第 3 步:engine + session(db.py,15 分钟)

新建 `src\w2d3_sqlalchemy_todo\db.py`:

```python
"""数据库通道:engine(连接池)+ session 工厂 + FastAPI 依赖。"""
from collections.abc import Generator

from sqlalchemy import create_engine
from sqlalchemy.orm import Session, sessionmaker

from w2d3_sqlalchemy_todo.config import settings

if not settings.database_url:
    raise RuntimeError("TODO_DATABASE_URL 未配置,请复制 .env.example 为 .env")

engine = create_engine(settings.database_url, echo=settings.debug)
# echo=True:每条 SQL 都打印出来,学 ORM 最有用的开关

SessionLocal = sessionmaker(bind=engine)
# 默认 expire_on_commit=True:commit 后对象属性"过期",
# 下次访问会重新 SELECT —— 所以 create/update 后要 db.refresh() 取回数据库最终状态

def get_db() -> Generator[Session, None, None]:
    """FastAPI 依赖:每个请求发一个 session,请求结束关闭(归还连接,防泄漏)。"""
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

class TodoNotFoundError(Exception):
    def __init__(self, todo_id: int):
        self.todo_id = todo_id
        super().__init__(f"待办 {todo_id} 不存在")
```

要点:
- **engine 只建一次**(应用级单例);**session 每个请求一个**(用完即还);
- `get_db` 是 FastAPI 依赖注入:端点参数写 `db: Session = Depends(get_db)` 就能拿到本请求专属的 session;
- 这就是昨天 docker run 时 `-v` 卷的意义:数据存在 PG 的数据目录里,和 API 进程无关。

## 📖 第 4 步:改造 main.py(25 分钟)

新建 `src\w2d3_sqlalchemy_todo\main.py`(对照 w1d7 逐段改):

```python
from contextlib import asynccontextmanager
import time

from fastapi import Depends, FastAPI, Request
from fastapi.responses import JSONResponse
from sqlalchemy import select
from sqlalchemy.orm import Session

from w2d3_sqlalchemy_todo.config import settings
from w2d3_sqlalchemy_todo.db import SessionLocal, TodoNotFoundError, engine, get_db
from w2d3_sqlalchemy_todo.models import Base, Todo
from w2d3_sqlalchemy_todo.schemas import TodoIn, TodoOut, TodoUpdate

@asynccontextmanager
async def lifespan(app: FastAPI):
    Base.metadata.create_all(engine)        # 表不存在就建(周四换成 Alembic)
    with SessionLocal() as db:              # 首次启动预置一条;PG 持久化,重启不会重复种
        if db.get(Todo, 1) is None:
            db.add(Todo(title="完成第 1 周综合练习"))
            db.commit()
    print(f"[lifespan] {settings.app_name} 已启动")
    yield

app = FastAPI(title=settings.app_name, lifespan=lifespan)

@app.middleware("http")
async def add_process_time_header(request: Request, call_next):
    start = time.perf_counter()
    response = await call_next(request)
    elapsed = time.perf_counter() - start
    response.headers["X-Process-Time"] = f"{elapsed:.6f}"
    return response

@app.exception_handler(TodoNotFoundError)
async def todo_not_found_handler(request: Request, exc: TodoNotFoundError):
    return JSONResponse(status_code=404, content={"error": "not_found", "message": str(exc)})

# C:创建
@app.post("/todos", response_model=TodoOut, status_code=201)
def create_todo(todo: TodoIn, db: Session = Depends(get_db)):
    obj = Todo(**todo.model_dump())
    db.add(obj)                 # 只是挂到 session,还没发 SQL
    db.commit()                 # INSERT 在这一刻发出,id 由 PG 序列生成
    db.refresh(obj)             # commit 后对象过期,refresh 取回数据库最终状态
    return obj

# R:查列表 + 查单条
@app.get("/todos", response_model=list[TodoOut])
def list_todos(db: Session = Depends(get_db)):
    return db.scalars(select(Todo).order_by(Todo.id)).all()

@app.get("/todos/{todo_id}", response_model=TodoOut)
def get_todo(todo_id: int, db: Session = Depends(get_db)):
    obj = db.get(Todo, todo_id)          # 按主键取一行;内存版 6 行循环变 1 行
    if obj is None:
        raise TodoNotFoundError(todo_id)
    return obj

# U:局部更新
@app.patch("/todos/{todo_id}", response_model=TodoOut)
def update_todo(todo_id: int, todo: TodoUpdate, db: Session = Depends(get_db)):
    obj = db.get(Todo, todo_id)
    if obj is None:
        raise TodoNotFoundError(todo_id)
    for key, value in todo.model_dump(exclude_unset=True).items():
        setattr(obj, key, value)     # 改对象属性,session 自动标记"脏"
    db.commit()                      # UPDATE 只包含改过的列(echo 里亲眼验证)
    db.refresh(obj)
    return obj

# D:删除
@app.delete("/todos/{todo_id}", status_code=204)
def delete_todo(todo_id: int, db: Session = Depends(get_db)):
    obj = db.get(Todo, todo_id)
    if obj is None:
        raise TodoNotFoundError(todo_id)
    db.delete(obj)
    db.commit()
```

改造对照表:

| w1d7(内存 dict) | w2d3(ORM) | 说明 |
|---|---|---|
| `for t in db["todos"]: if t["id"]==...` | `db.get(Todo, todo_id)` | 按主键查一行,没有返回 None → 404 |
| `db["todos"].append(record)` | `db.add(obj)` + `db.commit()` | add 不落库,commit 才发 INSERT |
| `t.update(...)` | `setattr(obj, k, v)` + `commit()` | 脏跟踪:只 UPDATE 改过的列 |
| `db["todos"].pop(i)` | `db.delete(obj)` + `commit()` | 标记删除,commit 发 DELETE |
| 启动 `reset_db()`(每次都重置) | 只在表空时预置(数据持久) | **重启不再丢数据** —— 今天要亲手验证的体验 |

要点:
- `select(Todo)` 是 2.0 查询 API(老教程的 `db.query(Todo)` 已过时);
- `db.scalars(...)` 从结果里取对象(不带它拿到的是元组行);
- **add / commit / refresh 三连**的时机:add 只是"记账",commit 才"发工资",refresh 是"对账"。

## 🔗 第 7 步:关系映射 school_demo.py(25 分钟)

前面的 Todo 是单表。**relationship** 才是 ORM 的杀手锏:把昨天手写的 JOIN 变成"顺着对象走"。新建 `src\w2d3_sqlalchemy_todo\school_demo.py`,给 w2d2 的 school 三张表写模型(它们已经在 PG 里了,不用建表):

```python
"""school_demo.py:给 school 三张表写 ORM 模型,体会 relationship。"""
from decimal import Decimal

from sqlalchemy import ForeignKey, String, create_engine, func, select
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column, relationship

engine = create_engine(
    "postgresql+psycopg://postgres:postgres@localhost:5432/school", echo=True
)

class Base(DeclarativeBase):
    pass

class Student(Base):
    __tablename__ = "students"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String)
    class_id: Mapped[int]
    enrollments: Mapped[list["Enrollment"]] = relationship(back_populates="student")

class Course(Base):
    __tablename__ = "courses"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String)
    credit: Mapped[Decimal]              # NUMERIC 列 ↔ Python Decimal(精确小数)
    enrollments: Mapped[list["Enrollment"]] = relationship(back_populates="course")

class Enrollment(Base):
    __tablename__ = "enrollments"
    student_id: Mapped[int] = mapped_column(ForeignKey("students.id"), primary_key=True)
    course_id: Mapped[int] = mapped_column(ForeignKey("courses.id"), primary_key=True)
    score: Mapped[Decimal | None]        # NULL = 缺考
    student: Mapped[Student] = relationship(back_populates="enrollments")
    course: Mapped[Course] = relationship(back_populates="enrollments")

with Session(engine) as db:
    # 1. 张伟的所有选课(等价周一 JOIN 三表的 SQL,但不用写 JOIN):
    zhangwei = db.scalar(select(Student).where(Student.name == "张伟"))
    for e in zhangwei.enrollments:       # 访问属性 = 自动发查询(lazy load)
        print(f"[1] {e.course.name}: {e.score}")

    # 2. 反向走:数学课有哪些人选了:
    math = db.scalar(select(Course).where(Course.name == "数学"))
    for e in math.enrollments:
        print(f"[2] {e.student.name}: {e.score}")

    # 3. 每个学生的平均分(ORM 版 GROUP BY,呼应周一 challenge 第 2 题):
    rows = db.execute(
        select(Student.name, func.avg(Enrollment.score).label("avg"))
        .join(Enrollment)
        .group_by(Student.id)
        .order_by(Student.id)
    ).all()
    for name, avg in rows:
        print(f"[3] {name}: {avg:.2f}")
```

> 注意打印别用 ✅/❌ emoji(GBK 控制台坑,周一的教训)。

概念要点:
- **外键 `ForeignKey("students.id")`** 定义"列之间的引用";**`relationship()`** 定义"对象之间的引用",`back_populates` 让两边互指;
- 学生选课是"多对多,但选课表带成绩列"——所以 enrollments 不是纯关联表,而是一个**真模型**(关联对象模式),student/course 两端都指向它;
- `e.course.name` 这种写法背后是 lazy load:第一次访问 `.enrollments` 时才发 SELECT(echo 窗口能看得一清二楚)。

### 然后,踩昨天预告的坑(必做)

在 `with Session(engine) as db:` 里加一段,**插入一个不写 id 的学生**:

```python
    db.add(Student(name="新同学", class_id=1))
    db.commit()
```

预期报错:

```
psycopg.errors.UniqueViolation: duplicate key value violates unique constraint "students_pkey"
DETAIL: Key (id)=(1) already exists.
```

**为什么?** 昨天 seed.sql 显式插了 id=1~6,但 SERIAL 序列不知道,还停在 1 → 第一个 `nextval` 给了 1 → 撞上已有的张伟。这就是昨天指导里说的"周三再细说"。

修复(psql 里,把序列推进到当前最大值):

```powershell
docker exec -i pg-school psql -U postgres -d school -c "SELECT setval(pg_get_serial_sequence('students','id'), (SELECT MAX(id) FROM students));"
```

> `pg_get_serial_sequence('表','列')` 自动找到该列的序列名,`setval` 把它推进到 MAX(id)。courses 表同理。真实项目中:要么迁移工具(Alembic,明天学)管理,要么显式 id 插入后手动 setval——今天你两个都见过了。
