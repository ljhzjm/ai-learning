## 🎯 先懂四个要素(15 分钟)

| 要素 | 作用 | 例子 |
|---|---|---|
| **角色(role/system)** | 定人设:领域知识、语气、视角 | 「你是一位三甲医院睡眠科医生」 |
| **指令(instruction)** | 要做什么 | 「把下面的新闻标题分类」 |
| **约束(constraints)** | 怎么输出、不许做什么 | 「只输出类别名称,不要解释」 |
| **few-shot** | 用 2~3 个示例教格式 | 「标题:皇马夺冠 → 类别:体育」 |

关键认知:**模型不是你的下属,它只是一五一十执行你写的东西**。输出质量的上限由 prompt 决定;而 few-shot 教的是"格式",不是"知识"——这点今天实验 3 会亲自验证。

写一个 `src/w3d3_prompt_basics/ask.py`,四个实验脚本共用(今天你会发十几次请求,别复制粘贴请求代码):

```python
"""公共函数:发一次 chat 请求,返回 (回答内容, usage)。"""

import httpx

from w3d3_prompt_basics.settings import Settings


def ask(s: Settings, messages: list[dict], max_tokens: int = 300) -> tuple[str, dict]:
    r = httpx.post(
        f"{s.base_url}/chat/completions",
        headers={"Authorization": f"Bearer {s.api_key}"},
        json={"model": s.model, "messages": messages, "max_tokens": max_tokens},
        timeout=60,
    )
    r.raise_for_status()
    data = r.json()
    return data["choices"][0]["message"]["content"], data["usage"]


def system_user(system: str | None, user: str) -> list[dict]:
    """拼 messages:有 system 就带,没有就纯 user(用于无角色对照组)。"""
    if system:
        return [{"role": "system", "content": system}, {"role": "user", "content": user}]
    return [{"role": "user", "content": user}]
```

## 📦 实验 1:角色对比(25 分钟)——exp1_role.py

同一个问题「我最近睡眠不好,有什么建议?」,换 4 种角色,各问一次,回答打印成 4 段:

1. **无角色**(不用 system_user 的 system,直接纯 user)
2. 你是一位三甲医院睡眠科医生
3. 你是一位健身教练
4. 你是一位说话爱用比喻的东北大爷

观察:答案的知识深度、语气、视角哪里不同?把一句话结论写进笔记:**角色 = 领域 + 语气 + 视角的总开关**。

## 📦 实验 2:约束对比(25 分钟)——exp2_constraint.py

同一个任务「什么是 Docker?」,3 种约束各问一次:

1. 无约束
2. 「用 3 个要点回答,每个要点不超过 15 个字,不要寒暄,不要结尾总结」
3. 「先给一句话结论,再给两个理由,最后给一个类比」

观察:模型服从约束的程度;约束越**具体、可验证**,服从越好。笔记结论:**约束要写成"能检查"的标准,而不是"写得好一点"这种空话**——这正是周四结构化输出(JSON mode)的动机:靠自然语言约束格式不稳定,靠机制强制格式才 100% 可靠。

## 📦 实验 3:few-shot 对比,今天的重头戏(35 分钟)——exp3_fewshot.py

分类任务:把 8 条新闻标题分到「科技/体育/娱乐/财经」四类,**逐条调用**,对比 zero-shot 和 few-shot 的输出:

```python
TITLES = [
    "苹果发布新一代自研芯片,性能提升 40%",
    "国足客场 2:1 逆转对手,晋级希望重燃",
    "某明星新片票房突破 20 亿",
    "央行宣布降准 0.5 个百分点",
    "开源大模型在数学竞赛中首次超过人类金牌选手",
    "湖人队签下全明星后卫,下赛季阵容豪华",
    "某综艺节目因版权问题下架",
    "A 股三大指数集体收涨,北向资金净流入超百亿",
]

ZERO_SHOT = "把下面的新闻标题分类到:科技、体育、娱乐、财经。只输出类别名称,不要解释。标题:{title}"

FEW_SHOT = """把下面的新闻标题分类到:科技、体育、娱乐、财经。只输出类别名称。
示例:
标题:某公司发布折叠屏手机 → 科技
标题:国乒包揽世锦赛全部金牌 → 体育
标题:某上市公司股价连续三日涨停 → 财经
标题:{title}"""
```

对比两组输出:**zero-shot 偶尔会输出「这条新闻属于科技类」这种带解释的长句,few-shot 几乎全部只输出干净的「科技」**。结论写进笔记:**few-shot 用示例示范"输出格式",让输出可以直接被程序消费**(字符串比较/落库)——这是 LLM 应用和"聊天"的分水岭。有余力再把 8 条的准确率数一数(分类对不对,你说了算,顺便练了标注)。

## 📦 信息抽取(20 分钟)——extract.py

分类是"选一个标签",抽取是"从文本里把东西抠出来"。给一段新闻:

> 2026 年 9 月 12 日,人工智能公司星辰科技 CEO 李明在北京召开发布会,宣布完成 3 亿元 B 轮融资,投资方包括红杉资本。新产品将于 10 月 15 日在上海发布。

Prompt:「从下面的新闻中抽取人名、公司名、地点、日期、金额,严格按
`人名:... / 公司:... / 地点:... / 日期:... / 金额:...` 一行一个字段输出,不要输出其他内容。」先 zero-shot 抽一次,再加一个示例(few-shot)抽一次,对比格式稳定性。笔记结论:**程序要消费输出,格式必须稳定;而格式稳定最终要靠周四的结构化输出机制**。
