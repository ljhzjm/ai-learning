## 🎯 先懂 5 个 Docker 概念(10 分钟)

| 概念 | 一句话解释 |
|---|---|
| **镜像(image)** | 打包好的"软件安装包"(含操作系统+程序+依赖),只读。`docker pull` 下载 |
| **容器(container)** | 镜像的**运行实例**,类似"程序进程"。一个镜像可以起多个容器,互不干扰 |
| **端口映射 `-p`** | 容器内部是隔离的网络。`-p 5432:5432` = 把容器里的 5432 端口"转发"到 Windows 的 5432,外部才能连 |
| **数据卷 `-v`** | 容器删除后内部数据**全没**。`-v pg-school-data:/var/lib/postgresql/data` 把数据存到 Docker 管理的"卷"里,删容器重建数据还在 |
| **环境变量 `-e`** | 向容器"注入配置"。postgres 镜像要求必须给 `POSTGRES_PASSWORD` |

> 容器 vs 虚拟机:虚拟机装完整操作系统(几个 G 起步),容器只共享宿主机内核、按需打包依赖(几十 M 起步),秒级启动。这就是为什么 PG 不用装、一条命令就跑起来。

> `docker exec -it 容器名 命令` = "进到容器里执行命令",是排查容器最常用的操作。`-it` 表示交互式终端。

## 📖 第 2 步:psql 常用命令(15 分钟)

psql 里以 `\` 开头的叫**元命令**(不是 SQL,是 psql 客户端的操作命令):

| 命令 | 作用 | SQLite 对应 |
|---|---|---|
| `\l` | 列出所有数据库 | - |
| `\c 数据库名` | 切换数据库 | - |
| `\dt` | 列出当前库所有表 | `.tables` |
| `\d 表名` | 看表结构(列、类型) | `.schema 表名` |
| `\di` | 列出所有**索引** | - |
| `\?` | 查看全部元命令帮助 | `.help` |
| `\q` | 退出 | `.quit` |

> 注意:SQL 语句末尾必须带 `;`,元命令不用分号。

## 📖 第 3 步:建表 + 播种(30 分钟)

新建项目 `practice/w2d2-pg-basics/sql/`(今天纯 SQL + Docker,不需要 uv 项目),写 `schema.sql`:

```sql
-- schema.sql:PG 版 school 建表(对比昨天 SQLite 的 setup.py)
-- 开头 DROP 是为了重复执行不报"表已存在"
DROP TABLE IF EXISTS enrollments, students, courses;

CREATE TABLE students (
    id SERIAL PRIMARY KEY,          -- SQLite: INTEGER PRIMARY KEY
    name TEXT NOT NULL,
    class_id INTEGER NOT NULL
);
CREATE TABLE courses (
    id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    credit NUMERIC(3,1) NOT NULL    -- SQLite: REAL
);
CREATE TABLE enrollments (
    student_id INTEGER NOT NULL,
    course_id INTEGER NOT NULL,
    score NUMERIC(4,1),             -- NULL = 缺考
    PRIMARY KEY (student_id, course_id)
);
```

**PG 与 SQLite 的差异点**(面试常问):

| SQLite | PostgreSQL | 说明 |
|---|---|---|
| `INTEGER PRIMARY KEY` | `SERIAL PRIMARY KEY` | SERIAL = 自动创建自增序列,插入时不写 id 自动 +1 |
| `REAL` | `NUMERIC(4,1)` | PG 里 NUMERIC 是精确小数,REAL 是浮点;NUMERIC(4,1)= 共 4 位、小数点后 1 位 |
| 标识符不区分大小写 | 未加双引号的标识符**折成小写** | `CREATE TABLE Students` 实际表名是 `students` |
| 单引号字符串 | 单引号字符串,**双引号是标识符** | `WHERE name = '张伟'`;`"name"` 是列名 |

## 📖 第 4 步:5 类查询原样重跑 + 差异对比(40 分钟)

把昨天 challenge.py 里的 5 道题在 psql 里重跑。**语法 90% 一致**,重点感受差异:

1. `SELECT name FROM students WHERE class_id = 2 ORDER BY id;` — 一样
2. `SELECT student_id, AVG(score) ... GROUP BY ... HAVING AVG(score) >= 80;` — 一样,但 **AVG 结果是 `88.333333333333`(PG 默认精度更高)**,SQLite 是 `88.33`
3. 子查询 `IN (...)` / `NOT IN (...)` — 一样
4. JOIN — 一样
5. **EXPLAIN 完全不同**(今天的重头戏):

```sql
EXPLAIN SELECT * FROM enrollments WHERE student_id = 3;
-- PG 输出树状计划:
-- Seq Scan on enrollments  (cost=0.00..1.21 rows=4 width=44)
--   Filter: (student_id = 3)          ← 全表扫描,等价 SQLite 的 SCAN

CREATE INDEX idx_enr_student ON enrollments(student_id);

EXPLAIN SELECT * FROM enrollments WHERE student_id = 3;
-- Index Scan using idx_enr_student on enrollments ...   ← 等价 SQLite 的 SEARCH

EXPLAIN ANALYZE SELECT * FROM enrollments WHERE student_id = 3;
-- ANALYZE 会**真正执行**查询,打印真实耗时:
-- Execution Time: 0.045 ms   ← SQLite 没有这个,PG 独家
```

> 要点:① `EXPLAIN` 只看计划不执行,`EXPLAIN ANALYZE` 真跑并测速(小表数据量太小,Index Scan 可能比 Seq Scan 还"慢",正常——几百行全扫本来就快,索引的价值在**大表**);② 看懂三个关键词:**Seq Scan**(全表扫,慢)、**Index Scan**(走索引,快)、**Filter**(WHERE 条件在哪一步过滤);③ cost 是估算代价,行数×宽度越小越便宜。
